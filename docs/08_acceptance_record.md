### 14.4 当前主要问题

- 部分 OCR 文本含表格碎片、页眉页脚和 HTML 残留；
- 页码缺失较多，部分记录没有稳定 `clause`；
- 同类设备故障机理分散在不同领域中；
- 向量检索对长 OCR 文本和通用描述不够敏感；
- BM25 对专业术语有效，但仍依赖查询扩展；
- RRF 只能使用排名，不能直接判断证据是否真正回答问题；
- 当前依赖 `candidate_k=300` 的较大候选池保证召回；
- v3 分层知识库本体和索引通过校验，但 `data/rules/failure_mode_rules.json` 的中文内容损坏，暂不能接入规则层；
- 即使 current 回归 7/7 通过，也不能据此宣称通用设备问答已全部达标。

### 14.5 改进方向

1. 对原始 OCR 文件重新切块，保留章节、条号、页码和原始行号。
2. 补齐 v3 规则文件编码，并接入 `scope / evidence_kind / applies_to`。
3. 建立“具体设备证据 + 通用故障模式证据”的双路检索。
4. 对融合后的候选增加 Reranker。
5. 用查询规划替代 `candidate_k=300` 的临时扩池。
6. 扩大 current 组用例，覆盖锅炉、汽轮机、发电机、辅机和安全操作。
7. 将真实 DeepSeek API 测试作为可选高成本回归，而不是每次执行。
8. 继续评估答案表述与证据之间的关系，而不仅是条号存在性。
