# 向量检索按域加载优化报告

> 测试日期：2026-10-03
> 优化目标：避免每次从 SQLite 读取全部 15,188 条向量
> 实现：`vector_kb/retrieval.py`
> 基线：`docs/性能基准测试.md`

## 1. 优化内容

- `_load_knowledge()` 增加 `domains` 参数，知识库 schema 使用 `WHERE domain IN (...)` 在 SQLite 层过滤。
- 启动时检查 `knowledge(domain)` 是否已有索引；没有时创建 `idx_knowledge_domain`。
- `retrieve()` 增加进程内向量缓存，缓存键为 `(db_path, domain)`。
- `domains` 为空时仍读取全表并缓存为 `__all__`，保持旧行为。
- 多域查询按域分别加载，再合并候选集合。
- debug 输出增加：
  - `[向量库缓存] 命中/未命中 domain=...`
  - `[向量库] 加载域=... 条数=... 耗时=...s`

未修改向量检索算分、阈值过滤或最终排序逻辑。

## 2. 优化前后对比

| 指标 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---:|
| 向量检索阶段：`汽轮机振动` | 2.001s | 0.717s | 降低 64.17% |
| `load_vectors`：turbine 域 | 1.451s | 0.283s | 降低 80.50% |
| 同域缓存命中后的向量检索 | - | 0.417s | 低于 0.5s |
| 首次查询后内存 | 2,519.72 MB | 506.07 MB | 降低 79.92% |
| 第二次查询后内存 | 2,541.04 MB | 869.45 MB | 低于 1 GB |

说明：优化后的 `0.717s` 包含 Ollama query embedding 时间；真正的 turbine 向量加载耗时约 `0.283s`。

## 3. 按域加载与回退验证

| 场景 | 加载范围 | 条数 | 加载耗时 | 向量阶段耗时 |
|---|---|---:|---:|---:|
| `汽轮机振动` → `turbine` | `WHERE domain='turbine'` | 3,230 | 0.283s | 0.717s |
| `汽轮机振动导致轴承温度高` → `turbine + auxiliary` | 两个域分别加载 | 4,608 | 0.282s + 0.114s | 1.020s |
| 不传 `domains` | 全表 | 15,188 | 1.327s | 3.060s |

多域查询日志确认同时加载 `turbine` 和 `auxiliary` 两个域；无域查询仍走全表回退。

## 4. 结果一致性

- `knowledge` 表已有 `idx_knowledge_domain` 索引；实现保留“缺失时自动创建”逻辑。
- SQL 过滤只减少加载行数，不改变向量余弦计算公式和 Top-K 排序。
- 对 `汽轮机振动` 比较全表加载后域过滤与 SQL 按域加载，Top-10 条号顺序一致。
- 同域第二次调用走进程内缓存。
- 回归测试结果：

| 组别 | 通过 | 失败 | 已知 |
|---|---:|---:|---:|
| legacy | 23/24 | 0 | 1 |
| current | 7/7 | 0 | 0 |

## 5. 结论

向量冷加载从全表的 `1.451s` 降到 turbine 域的 `0.283s`，向量检索阶段从 `2.001s` 降到 `0.717s`。首次查询后内存低于 1 GB，多域查询和无域回退行为均通过验证。当前剩余主要耗时来自 Ollama embedding 和 DeepSeek 生成。
