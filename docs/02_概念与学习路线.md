### 阶段 0：工具与工程习惯（第 1 周，边做边学）
- ✅ 命令行/终端（PowerShell）：cd、ls、dir、运行 `python xx.py`
  为什么：所有装环境、跑程序都在终端发生。
- ✅ Git 与 GitHub：仓库(repo)、commit、push、clone、README、.gitignore
  为什么：技术向考核就是「提交 GitHub 仓库」；开发日志/日程记录也要进仓库。
- ✅ Python 环境三件套：解释器、pip、虚拟环境(venv)
  为什么：AGENTS.md 技术栈是 Python；venv 保证两人环境一致，`requirements.txt` 记录依赖。
- ✅ API Key 与 `.env` 环境变量
  为什么：DeepSeek 等 API 要密钥；**绝不能让 key 出现在 GitHub 上**（用 .gitignore 排除）。
- ✅ Markdown：写 README、架构文档、开发日志。
- 🔎 VSCode 编辑器基本操作。

### 阶段 1：Python 基础（够用即止，不是学完）
- ✅ 变量与类型、字符串、数字
- ✅ 列表 list、字典 dict（大量代码围绕 dict/json 转来转去）
- ✅ 条件 if / 循环 for / 函数 def
- ✅ 读写文件、读 JSON（知识库语料要读进来）
- ✅ try/except 异常处理（调 API 网络失败要兜底）
- 🔎 类与对象的最基本概念（LangChain 是面向对象的，读报错/文档需要）
- ❌ 暂不需要：多线程、装饰器、算法、正则深入——遇到再查。

### 阶段 2：大模型与 API 基础
- ✅ 大语言模型(LLM)是什么：输入文本→输出文本的概率模型
- ✅ 大模型 API：用代码请求远程模型（本项目 DeepSeek），不是本地跑大模型
- ✅ Prompt / 提示词：system(设定角色规则)+user(提问) 两条消息
- ✅ token：模型计费与窗口的单位，≈ 汉字/英文子词
- ✅ temperature：越低越保守稳定（诊断输出应设低）
- ✅ 幻觉(hallucination)：模型会一本正经编造 → 这就是要建知识库的原因
- 🔎 结构化输出/JSON 输出：让回答能被程序解析（进阶）
- 验收：调通 DeepSeek，输入"一句话介绍变压器"，能打印返回结果。

### 阶段 3：RAG 核心概念（本项目的心脏，最高优先级）
- ✅ 为什么用 RAG：模型没学过你们私有规程 → 先检索相关条文，再让模型"看着条文回答"
- ✅ 文档切分(chunking)：长规程切成小块（几百字/块）
  为什么：检索以"块"为单位，切太碎丢上下文、太整检索不准。
- ✅ Embedding / 向量化：把一段文字变成一串数字(向量)，语义相近→向量相近
- ✅ 向量相似度 / 余弦相似度：衡量"哪块最相关"的数学
- ✅ 向量数据库（Chroma）：存向量、按相似度查 Top-k
- ✅ 检索(retrieval)：拿用户问题→查最相关的几块
- ✅ 生成(generation)：把"问题+检索到的条文"一起给 LLM → 输出带引用的回答
- ✅ 引用溯源(citation)：回答标注"依据 DL/T 722 某条" → 对抗幻觉、满足考核"可溯源"
- ✅ 未命中拒答：知识库没有就答"资料中未覆盖"，不硬编
- 🔎 混合检索/重排序(rerank)：关键词+向量结合、二次精排（有则加分）
- 验收：用任意一篇中文文档（如社团题目 PDF 的文字版）跑通「提问→检索→回答带引用」。

### 阶段 4：框架与组件（把概念变成代码）
- ✅ LangChain：封装"切分→向量化→入库→检索→生成"的库（对应技术栈）
- ✅ Chroma：向量数据库（上面已讲）
- ✅ HuggingFace Embedding 模型：用开源的**中文** embedding（如 BGE 系列）做向量化
- ✅ DeepSeek API：生成模型（api-docs.deepseek.com）
- 🔎 LangGraph：把多步流程画成"状态图"的库（做 Agent 工作流时用）
- 🔎 LCEL / LangChain 链式写法、Runnable 概念（报错时看得懂）
- 验收：把阶段 3 的 demo 换成「Chroma + LangChain + DeepSeek」实现。

### 阶段 5：Agent 概念（考纲点名要设计 Agent Workflow，最简理解即可）
- ✅ Agent = LLM + 工具/检索 + 多步循环决策（不是一问一答）
- ✅ ReAct：Reason(想)→Act(做/查)→Observe(看结果)→再想…… 循环
  为什么：排障要先查规则→形成假设→再查证→最后出报告。
- 🔎 工具调用(tool/function calling)：让模型决定"调用哪个检索/计算函数"
- 🔎 状态与记忆：多步排查要记住"已经查过什么、得到什么"
- 🔎 反思(Reflexion)、GraphRAG、MCP：有印象即可，报告里能提一句
- 验收：画出你们排障的 4~5 步流程图（现象→检索→假设→验证→报告）。

### 阶段 6：变压器/电气领域概念（只要够建知识库，不必懂电气专业课）
- ✅ 变压器与油浸式电力变压器：绕组+铁芯+套管+变压器油+有载分接开关等构成
- ✅ 变压器油 / 油纸绝缘：油既绝缘又散热，过热/放电会让油纸分解产气
- ✅ DGA：油中溶解气体分析——看"油里冒了什么气"判断内部故障
- ✅ 特征气体：H2(氢) CH4(甲烷) C2H6(乙烷) C2H4(乙烯) C2H2(乙炔) CO CO2，各自指向过热/放电
- ✅ 故障类型：局部放电、火花放电、电弧放电、低温/中温/高温过热、受潮、老化
- ✅ 判据方法：注意值、三比值/改良三比值、Duval 三角
- ✅ 关键标准：DL/T 722-2014（国内）、IEC 60599:2022（国际）
- ✅ 现象→机理→部件→处置 的知识链（知识库按这个组织）
- 🔎 处置/合规：停电隔离、GB 26860 安全边界、检修流程、轻/重瓦斯、继电保护动作
- 🔎 产气速率、注意值表怎么读（做规则对照评测时用）
- 验收：拿到一组气体数据，能说出"像哪种故障、依据标准哪部分"。

### 阶段 7：评测与"闭环"验收
- ✅ 什么是闭环：输入异常现象 → 知识检索 → 推理 → 输出规范化根因报告
- ✅ 评测：诊断结论对错（对照 DL/T 722 判据）、检索是否命中、引用是否真实
- 🔎 RAGAS 指标：忠实度(faithfulness)、相关性(relevance)——报告里加分项
- 🔎 消融对比：有知识库 vs 无知识库 的输出对比 → 证明 RAG 的价值（答辩亮点）
- 🔎 危险提问拦截测试：故意问知识库外/危险操作，验证系统会拒答

### 阶段 8：交付物（考纲原文要求）
- GitHub 仓库：代码 + 架构文档 + 最小原型 + 使用说明 + 开发日志与日程记录
- 每周末写开发日志（做了什么/卡在哪/下一步）——这也是给评委看的"过程证据"

### 评委可能问、你们要能答的 5 问
1. 为什么用 RAG 而不是微调？→ 规程更新快/私有文档多，RAG 免训练、可换文档、可溯源；微调贵且会学进幻觉。
2. 向量检索和关键词检索区别？→ 向量懂语义（"乙炔高"≈"放电"），关键词只认字面；可混合用。
3. 怎么防幻觉？→ 只允许基于检索到的条文回答 + 强制引用 + 未命中拒答 + 低 temperature。
4. 为什么用 Agent 而不是一次生成？→ 排障是多步验证过程：先查规则→假设→再取证→出报告，Agent 能循环检索并自我修正。
5. 结果准不准/合不合规？→ 用 IEC TC10/公开样本对照 DL/T 722 判据算正确率；危险建议拦截测试证明合规边界。

## 附：论文精读方法与模板（原 docs/02）

> 目标：为**任务一综述**与**方案设计**服务。原则——不追求"读完"，追求"能讲出来、能为我所用"。

### 一、三遍法（每篇限时，别死磕）
| 遍次 | 时间 | 看什么 | 产出 |
|---|---|---|---|
| ① 快扫 | 5–10 min | 标题/作者/年份/发表地、**Abstract**、**Conclusion**、所有图和表的标题 | 判断：与我相关吗？要不要精读？ |
| ② 精读 | 30–50 min | Introduction（背景+贡献列表）、Method（思路与架构图，公式看不懂先跳）、Experiments（设置+主要结果表）、Conclusion | 边读边填《论文精读卡》 |
| ③ 复盘 | 10 min | 合上 PDF，用自己的话写一遍 | "解决什么问题→怎么解决→效果→局限→对我哪节有用" |

### 二、每篇必抓的 7 个点（=精读卡字段）
1. **基本信息**：标题/作者/年份/来源/arXiv/DOI
2. **一句话问题**：它要解决什么
3. **痛点**：现有方法哪里不足
4. **核心思路**：方法+架构（图/流程，公式可跳）
5. **数据与实验**：用什么数据、怎么评估、关键数字
6. **结论与局限**：作者自己的结论和承认的问题
7. **对我有用在哪**：写进综述哪一节 / 支撑方案哪个设计（引用点）

> 填卡模板见 `docs/笔记/模板_论文精读卡.md`。

### 四、新手读英文论文的 5 条建议
1. 先看 **Abstract + Figures/Tables**，不要从头逐字读；
2. 用翻译工具辅助（DeepL/沉浸式翻译/知云），**整句译**，别逐词查；
3. **公式第一次看不懂就跳过**，不影响抓思路；
4. **限时**：泛读 15 min、精读 45 min、复盘 10 min；
5. 组会每人 **10 分钟讲一遍**（费曼法）：讲不清楚＝还没读懂。
