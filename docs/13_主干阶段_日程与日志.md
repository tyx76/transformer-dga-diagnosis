# 主干阶段 · 日程与日志（09-12 → 09-26）

> 阶段定义：把系统最窄的一条闭环跑通——**按条切块（带条号）→ 向量入库 → 检索 → 生成带引用的报告**。
> 验收标准（硬指标）：输入「乙炔超标该怎么处理」→ 能检索到 **DL/T 722-2014 第 9.3 节（注意值）与第 10.2 节（三比值法）** 相关条文，输出报告并**明确标注条号**；知识库未覆盖时**拒答**，不臆测。
> 编写日期：2026-09-11 ｜ 关联：docs/00（总状态）、docs/04（方案）、docs/09（总日志）、docs/12（规则基线）

## 一、本阶段做什么 / 不做什么

**做（主干四步）**
1. 语料切块：按条号切，每块带元数据 `doc_id / clause / title / text / page`
2. 向量入库：中文 Embedding + Chroma，建 `transformer_kb` 集合
3. 检索：输入问题 → Top-k 条文，输出必须带条号
4. 生成：DeepSeek 依据检索条文生成根因/处置报告，**强制引用**；未命中拒答

**不做（放阶段二/加分项）**
查询改写（HyDE）、重排（reranker）、关键词+向量混合检索、路由到规则/工具、自省纠错（Self-RAG/CRAG）、引用校验（RARR）、知识图谱、界面

> 说明：只做主干，但**接口要留出来**——检索、生成各自写成独立函数/类，未来换模块不推倒重写。

## 四、里程碑检查点（每个都必须过）

1. **切块检查点**：随机抽 20 条，条号与标准原文一致；表格（表3/表6/表7）不依赖 OCR，改用规则库。
2. **入库检查点**：向量库块数与切块数一致；元数据里 `clause` **非空**（这是上次提交包的硬伤）。
3. **检索检查点**：对 10 条验收问题，Top-5 中至少命中 1 条相关条文；能报出条号。
4. **生成检查点**：报告里每个结论都能指到条文；无依据时拒答。
5. **评测检查点**：检索命中率、引用正确率可复现；与规则基线（61.8%，docs/12）分开记录。

## 五、风险与预案

| 风险 | 预案 |
|---|---|
| Embedding 模型体积大（含 torch）装不动 | 先用轻量中文模型（如 bge-small-zh 512 维）或走在线 Embedding；主干不因模型卡住 |
| 722 扫描件表格 OCR 乱码 | 表格类数据只用成员2 核对过的规则库；向量库只放条文正文 |
| 切块丢条号 | 切块脚本内置校验：`clause` 为空直接报错，不入库 |
| 中文全文检索失效（unicode61 不分词） | 关键词兜底用 jieba + BM25，不依赖 Chroma 自带 FTS |
| 中文路径导致命令行乱码 | 统一用相对路径 + 项目根目录作为工作目录 |
| 贪多（想先做重排/图谱） | 本阶段只做四步，其他记到"阶段二待办" |
