### 1. 任务二要交付什么（先对齐验收口径）

2. **一套知识组织体系**：文档原文、条文、规则表、故障模式分层存放，每条知识**可溯源到条文**；
3. **能支撑排因分析**：输入"异常现象/数据"→ 定位候选故障类型与可能原因 → 输出带依据的根因与处置；
4. 落到代码：一个可复用的「文档 → 知识库」构建脚本 + 库结构（向量库/规则库），供任务3/4调用。

### 3. 真实"非结构化文本"长什么样（以 572-2021 为例）
- 结构：封面 → 前言（修订说明）→ 目录 → 章(1-8) → 条(如 7.2.1) → 段/表 → 附录A(资料性)。
- 条号是**溯源锚点**：如 `7.2.1 气体继电器保护信号动作时，应立即对变压器进行检查，查明动作的原因……`。
- 内容类型混排：叙述性条款（怎么做）、条件-动作条款（若……则应……）、表（注意值/负载表）、列表 a)b)c)（排查考虑因素）。
- Word 还原有少量瑕疵：条号标点错位（`7，2.1`、`7彐`）、个别乱码 → 需要清洗层（P2）统一规整。

### 4. 处理流水线（P1–P5）
### P1 语料盘点与版本校对
- 建 `data/语料/` + `语料清单.md`（命名规范 `<标准号>_<名称>_<类型>`，登记 状态/用途）。
- 每条知识带 `doc_id`（如 `DLT-572-2021`），版本错的一定先纠正（本项目已踩过一次：572 冒充 722）。

### P2 解析与清洗
- PDF→文本：多路兜底 = PyMuPDF(pymupdf，带 CMap) → 失败则 Word 无界面转换 → 仍乱码则 OCR（PaddleOCR/微信截图，中文）。
- 清洗规则：去页眉页脚/封面前言噪声；把 `7，2．1` 一类规整为 `7.2.1`；统一全半角；保留编号与表格标记。
- 产出：每份文档的**干净纯文本 + 表格另存**（如 `表：气体组分注意值` 单独抽成 CSV/JSON）。

### P3 结构感知切分（关键：保住"溯源"）
> 详细规范见 **docs/07_切条与元数据规范.md**（字段定义 / 条号规则 / 切分粒度 / 入库校验）。
- 按「章 → 条 → 款」层级切分，不以固定字数切。
- 每个块（chunk）带元数据：`doc_id / 标准号 / 条号 / 标题 / 页码 / 正文`。
- 例：`{doc_id:"DLT-572-2021", clause:"7.2.1", title:"气体继电器保护信号动作的处理", text:"……", page:23}`
- 向量库存正文、**元数据用于回答时标注「依据 DL/T 572-2021 §7.2.1」** → 满足"可溯源"。

### P4 规则与决策知识结构化（任务二的"知识提取"落点）
- 把"条件→动作/判断"条款转成**机器可读规则**（JSON），与原文条号一一对应。示例（据 572 §7.2.1 真实内容）：
```json
{
  "rule_id": "DLT572-7.2.1",
  "source": "DL/T 572-2021 §7.2.1",
  "trigger": "气体继电器保护信号动作",
  "actions": [
    "立即对变压器进行检查",
    "查明动作原因：积聚空气/油位降低/二次回路故障/变压器内部故障",
    "若继电器内有气体：记录气量、观察颜色、试验是否可燃",
    "取气样及油样做色谱分析（对照 DL/T 722 判据）"
  ],
  "decision": [
    {"if": "气体无色无臭不可燃 且 色谱判断为空气", "then": "可继续运行，消除进气缺陷"},
    {"if": "气体可燃 或 油中溶解气体分析结果异常", "then": "综合判断，必要时停运"}
  ]
}
```
- 需要从 **DL/T 722-2014**（待补）抽取的规则表：气体组分注意值表、产气速率、三比值编码规则（0/1/2 编码→故障类型）、对应处理建议。
- 规则来源统一打 `source`，评审/评测时逐条人工核对。

### P5 入库与关联（四层知识组织 L0–L3）
| 层 | 内容 | 存哪 | 谁用 |
|---|---|---|---|
| L0 原文层 | 清洗后的整篇正文 + 页/条号 | 文本文件 | 溯源校对 |
| L1 检索块 | P3 的带条号 chunk → 向量库(Chroma) | 向量库 | Agent 检索条文/案例 |
| L2 规则层 | P4 的 JSON 规则（故障判据/处置决策表） | 代码/JSON + 内存规则引擎 | 排因的确定性骨架 |
| L3 关系层（可选加分） | 故障模式：现象↔气体↔故障类型↔可能原因↔处置↔依据 | 小 KG 或字典表 | 多跳/解释，消融对比 |

### 5. 排因分析如何消费这套知识（把"知识"变成"结论"）
```
输入异常现象（如：乙炔超标 / 气体继电器信号动作）
  → L2 规则匹配：特征气体→候选故障类型（过热/放电…）＋依据条文
  → L1 检索：拉取相关条款原文与历史案例（带条号）
  → LLM 生成「根因链」：现象 → 故障类型 → 可能原因(部件/机理) → 证据 → 处置建议
  → 强制引用：每个结论挂 rule_id / clause（未命中即拒答）
  → 规则校验器 + 人工复核关口（合规底线）
  → 输出规范化根因报告
```
- 排因质量三要素：**规则给骨架（防幻觉）＋ 检索给证据（可溯源）＋ LLM 给组织与解释（可读）**——这正是 docs/03 选定的 B4 混合路线在任务二的落地。

### 6. 评测（任务二自己怎么算"做好"）

## 附：规则基线评测（原 docs/04）

> 日期：2026-09-11 ｜ 数据：`data/样本/dga_samples_uL_per_L.csv` ｜ 规则：`data/规则库/rules_DLT722_dga_draft.json` v0.3 ｜ 脚本：`scripts/dga_ratio.py`
> 用途：给“规则基线”一个可复现的数字，作为后续 RAG + LLM 方案的对比基线（考纲要求评测）。

### 1. 评测口径（关键，别省）
- **只评测“气体超注意值”的样本**：表3（变压器/电抗器）注意值 H2 > 150、总烃 > 150、C2H2 > 1（330kV及以上）/ 5（220kV及以下）。未触发注意值时**三比值法不适用**（DL/T 722-2014 §10.2.4 a）。
- **剔除“正常”标签**：三比值判断表（表7）中没有“正常”类别。
- **类别归并**：低温过热（两档）→ 低温过热；低能放电（含兼过热）→ 低能放电；电弧放电（含兼过热）↔ 数据集“高能放电”。
- **分母为 0**：分子也为 0 记为 <0.1；分子 > 0 记为 ≥3（脚本会标注“分母为0”）。

### 2. 结果
### 220kV 口径
- 带标签样本 2910：正常 740（剔除）、未触发注意值 280、未匹配 39 → **可评测 1851 条**
- 严格匹配 **16.2%**（标准细分 9 类 vs 数据集标签口径不同，仅作参考）
- **归并后匹配 61.8%**
- 按类（归并后）：高能放电 **79.1%**｜低温过热 72.4%｜中温过热 66.9%｜低能放电 62.5%｜高温过热 48.7%｜局部放电 44.3%

### 330kV 口径
- 可评测 1923 条，归并后 **60.6%**（各类与 220kV 口径接近）

### 3. 结论（写综述/答辩用）
1. 改良三比值法单独使用准确率约 **60–62%**，与已有文献区间一致——**规则基线可用，但有明显上限**；
2. 盲区集中在**高温过热、局部放电、复合故障**（表7 无“正常”类、未纳入产气速率、无固体绝缘专项判据）；
3. 这正是本项目选择**“规则 + RAG + LLM + 引用约束”混合路线**的依据：规则提供确定性骨架与合规依据，检索/LLM 覆盖规则盲区，评测用同一批样本对比基线；
4. 后续评测还应补充：**引用命中率、危险建议拦截率、人工复核通过率**等合规指标（生成类任务不能只看分类准确率）。
