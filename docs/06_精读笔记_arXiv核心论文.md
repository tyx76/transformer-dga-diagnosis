## 1. ReAct：推理与行动协同（Agent 基座）
- 文件：`文献/04_幻觉抑制_合规/F1_arXiv2210.03629_ReAct.pdf` ｜ Yao et al., ICLR 2023
- 核心：让 LLM **交替生成"推理轨迹(reason)"与"动作(act)"**：推理帮助规划/跟踪/处理异常，动作去调用外部工具（检索、查库）获取信息，观察结果后继续推理。
- 为什么重要：它证明"边想边查"比"一口气生成"在需要外部知识的任务上更准、更可解释。**这是你们 Agent 工作流（任务3）的基座**。
- 对本项目可用点：排障应设计成"现象→(推理)需要什么证据→(动作)检索规程/查气体数据→(观察)→再推理→出报告"的循环；报告里"为什么用 Agent 而非单次生成"引它 + E4。
- 精读指引：§3 方法（推理-行动交错）、§5 结果、局限一节；对比 Chain-of-Thought 那一段重点看。

## 2. Self-RAG：自反思决定"何时检索/是否引用"
- 文件：`文献/04_幻觉抑制_合规/F2_arXiv2310.11511_SelfRAG.pdf` ｜ Asai et al., ICLR 2024
- 核心：训练模型输出**反思标记**（是否检索 IsREL/相关、IsSUP/支持、IsUSE/有用），让模型自己决定要不要检索、检索结果是否够用。
- 对本项目可用点：对应任务3"不同排查阶段的知识检索时机"——不是每步都检索，而是"需要证据时再查、查到的先用自评过滤"。引用于工作流设计中"自适应检索"。
- 精读指引：§2 方法（反思 token、训练）、§4 消融；重点是"检索时机自适应"这条思路。

## 3. CRAG：检索错了怎么办（纠错）
- 文件：`文献/04_幻觉抑制_合规/F3_arXiv2401.15884_CRAG.pdf` ｜ Yan et al., ICLR 2024
- 核心：加一个**轻量检索评估器**给检索结果打分（准确/错误/模糊）：准确→直接精化利用（decompose-recompose）；错误/模糊→改用网络搜索等更可靠来源，避免"带病检索带病生成"。
- 对本项目可用点：对应题面"关键规则难检索"与防幻觉——检索质量把关层。可在工作流里加"检索置信度低→扩大/换检索或拒答"逻辑。
- 精读指引：§3 方法（评估器+纠错动作）、§4 实验（RAG 变体增益）；看它如何与普通 RAG 叠加。

## 4. GraphRAG：跨文档/全局问题的图谱检索
- 文件：`文献/02_知识增强路线/B2a_arXiv2404.16130_GraphRAG_主论文.pdf` ｜ Edge et al. (Microsoft), 2024
- 核心：先对语料做**实体/关系抽取建图 → 社区检测 → 社区层级摘要**，回答"全局性问题"（如整个语料主题）时用 map-reduce 综合，而不是只做 Top-k 块检索。
- 对本项目可用点：对应背景"拓扑关系难组织、跨文档关联检索"——若把"气体→故障→部件→处置"建成小图谱，能回答"哪些故障会同时涉及 X 部件"这类关联问题。**加分项**，MVP 不强制。
- 精读指引：§2（索引构建流水线）、§3（社区摘要/全局查询）；与"纯向量 RAG 在全局问题上的失败案例"一起看。

## 5. RCAgent：工业根因分析的 Agent 工程范式（直接对标）
- 文件：`文献/03_根因分析_Agent/C2_arXiv2310.16340_RCAgent.pdf` ｜ Wang et al., CIKM 2024
- 核心：面向**真实工业云环境根因分析(RCA)**的工具增强 Agent：给 LLM 配查询/分析工具，用 schema 引导压缩上下文、隐私安全设计、自我一致性聚合，效果显著优于 ReAct。
- 对本项目可用点：**最接近你们"排因分析 Agent"的对标工作**——它的"工具编排 + 结构化输出(schema) + 隐私/安全约束"直接可迁移到"检索规程 + 规则匹配 + 结构化根因报告"。写方案引用它说明设计依据。
- 精读指引：§3 框架（工具设定、prompting、schema 压缩、self-consistent 聚合）、§5 案例；重点抄它的"规范化报告"与"证据收集-聚合"两段。

## 6. RAG 综述（Naive/Advanced/Modular 三范式）
- 文件：`文献/02_知识增强路线/B1_arXiv2312.10997_RAG_Survey.pdf` ｜ Gao et al., 2023/2024
- 核心：把 RAG 演进分为 **Naive(朴素)→Advanced(高级：预检索/检索后处理/rerank)→Modular(模块化：可替换检索器、可加记忆/路由等)**，并给出检索、生成、增强的整体分类。
- 对本项目可用点：**综述写作的骨架引用**——用它的三范式描述"知识注入技术路线"（对应 docs/03 视角一），也帮你们给自己的 RAG 版本定位（你们是 Advanced→Modular 之间）。
- 精读指引：§2 三范式对比表、§4 检索技术（Hybrid/Self-RAG/CRAG 都归入 modular 检索）、§7 评估；不需要全读，按需查表。

## 7. RARR：生成后"查证-修订"，保证可归因（合规关键）
- 文件：`文献/04_幻觉抑制_合规/F4_arXiv2210.08726_RARR.pdf` ｜ Gao et al., ACL 2023
- 核心：两阶段——**研究(research)**：把模型输出拆成可验证片段、检索外部证据；**修订(revision)**：对无依据的表述改写为有出处版本，尽量保持原意。核心思想是"每个结论都能指到证据"。
- 对本项目可用点：对应"严谨结论难合规生成"——你们的报告生成后应加一道"逐条核对引用/删改无依据表述"的修订层（类似 F2 设计约束），保证"处置建议都有规程依据"。
- 精读指引：§3 方法（研究+修订两阶段、引用标注格式）、§4 归因评测（如何衡量"可归因"）；重点是把"引用标注"做成可评测的指标。
