# BM25 分片加载优化报告

> 测试日期：2026-10-03
> 优化目标：降低 `plant_kb` 首次 BM25 检索的冷加载时间和内存占用
> 基线：`docs/03_检索与排序/性能基准测试.md`
> 实现：`scripts/build_sharded_bm25.py` + `vector_kb/bm25_retriever.py`

## 1. 优化内容

- 从 `knowledge/plant_kb/data/knowledge.jsonl` 按 `domain` 生成 7 个 BM25 分片。
- 生成 `knowledge/plant_kb/index/bm25_manifest.json`，记录分片记录数和 SHA-256。
- 生成 `knowledge/plant_kb/index/lightweight_metadata.jsonl`，包含 `doc_id / clause / title / domain / citation / is_citable`。
- `bm25_retrieve()` 在 `domains` 非空时只加载对应分片：
  - 单域查询只加载 1 个分片；
  - 多域查询按域合并对应分片；
  - `domains` 为空时继续加载全量索引；
  - 分片在进程内按文件缓存。
- 分片索引使用全局 `df / avgdl / corpus_size` 计算分数，避免各域使用不同 IDF 尺度。
- 未修改 `knowledge.jsonl`、`knowledge.db` 和原有检索排序算法。

## 3. 优化前后对比

数据来源：

- 优化前：`docs/03_检索与排序/性能基准测试.md`
- 优化后：使用同一台机器、同一 `main.py` 调用链重新测量
- 查询：`汽轮机振动`
- 内存口径：进程 Working Set

| 指标 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---:|
| 首次 BM25 检索 | 9.978s | 0.862s | 降低 91.36% |
| 首次查询端到端总耗时 | 15.988s | 5.906s | 降低 63.06% |
| 向量检索 | 2.001s | 1.964s | 基本持平 |
| 生成 | 4.002s | 3.073s | 外部 API 波动 |
| 首次查询后内存 | 2,519.72 MB | 376.14 MB | 降低 85.07% |
| 第二次查询后内存 | 2,541.04 MB | 647.16 MB | 低于 1 GB |

首次 BM25 分片加载已进入 2 秒以内；主要剩余端到端耗时来自向量检索和 DeepSeek 生成。

## 4. 多域与回退验证

| 场景 | 加载分片 | 记录数 | 耗时 | 结果 |
|---|---|---:|---:|---|
| `汽轮机振动` | `bm25_turbine.pkl` | 3,230 | 0.862s | 通过 |
| `汽轮机振动导致轴承温度高` | `bm25_turbine.pkl` + `bm25_auxiliary.pkl` | 4,608 | 1.126s | 通过，结果包含两个域 |
| 不传 `domains` | 全量 `bm25_index.pkl` | 15,188 | 5.750s | 通过，旧行为保留 |

多域查询实测结果同时包含 `turbine` 和 `auxiliary` 域条文。

## 5. 结果一致性

- 对 `汽轮机振动` 比较全量索引和 turbine 分片的前 6 个有效结果，条文顺序一致。
- 分片使用全量语料的 `df`、`avgdl` 和 `corpus_size` 计算分数，域内评分公式与全量索引保持一致。
- 旧回归测试结果：

| 组别 | 通过 | 失败 | 已知 |
|---|---:|---:|---:|
| legacy | 23/24 | 0 | 1 |
| current | 7/7 | 0 | 0 |

## 6. 结论

BM25 冷加载瓶颈已经消除：单域首次检索从 `9.978s` 降至 `0.862s`，进程首次查询后内存从 `2,519.72 MB` 降至 `376.14 MB`。当前首要性能耗时转为向量检索和外部生成调用，BM25 不再是主瓶颈。
