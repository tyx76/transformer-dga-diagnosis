## 3. 典型问题

### 问题一：通用设备问题没有进入 plant_kb 的对应领域

例如：

- “过热器A侧二级减温水调节门内漏”被 LLM 兜底分类为 `safety_check`，路由到 `safety + dp`
- “排烟温度偏高”被分类为 `oil_temp`，路由到 `oil_temp`
- “第八级段特征通流面积略偏低”被分类为 `equipment_spec` 或 `dga_analysis`
- “励磁电流持续动态超限”被分类为 `safety_check`

当前意图类别只有：

`dga_analysis / oil_temp / safety_check / equipment_spec / irrelevant`

它没有面向锅炉、汽轮机、发电机通用故障的 `general_plant` 意图。通用设备问题会被 LLM 强行塞进现有类别，导致领域路由错误。

### 问题二：plant_kb 的 OCR 原始记录质量不足

直接调用 `plant_kb.search()` 后，候选记录中出现大量：

- 图片 HTML 标签
- 表格 HTML 片段
- 公式碎片
- 页眉页脚和编号噪声
- 缺少稳定条号或正文语义

例如通用锅炉问题会返回带有 `<div>`、`<img>`、表格标签的 OCR 片段，不能直接作为可引用的规程依据。

### 问题三：旧库兜底会把无关的变压器条款带入回答

当 `plant_kb` 没有已核验记录时，适配器会默认调用旧 `pure_kb` 做空结果兜底。对于锅炉、汽轮机、发电机问题，旧库返回的是 DL/T 572-2021 的变压器油温、停运、接地等条款，因此生成模型只能判定“资料未覆盖”。

## 4. 结论

本次测试证明：

1. `plant_kb` 的代码和数据库本身可用；
2. 真实 DeepSeek API 调用链可用；
3. 当前主链路不能直接支持通用电厂设备题库；
4. 主要瓶颈不是生成模型，而是“意图分类 + 知识库路由 + OCR 数据质量”；
5. 在不增加 `general_plant` 路由和清洗 OCR 语料之前，不应把 138 题通用测试集作为植物知识库的生产验收标准。

## 5. 下一步建议

1. 新增 `general_plant` 意图，覆盖锅炉、汽轮机、发电机关键词；
2. 路由映射到 `plant_kb` 的 `equipment`、`oil_temp`、`safety`、`cases` 等领域；
3. 对通用设备问题启用 `plant_kb` 未复核 OCR 数据前，先进行清洗：
   - 去除 HTML、图片标签、重复页眉页脚；
   - 恢复条号、章节和来源；
   - 人工复核后再标记为可引用证据；
4. 为通用设备问题单独定义 `allow_unreviewed` 策略，不要影响变压器 DGA 主链路的已核验优先策略；
5. 清洗后重新跑 24 题，再决定是否扩大到完整 138 题。
