# 138题评测集 evidence 结构与评估偏差分析

分析日期：2026-10-05
评测集：`data/samples/评测集/评测集/evaluation_dataset_final.json`
系统明细：`docs/04_评测与回归/exam_proof/138题评测明细_20261004.jsonl`
约束：只读分析，不修改评测集。



## 1. 结论摘要

1. evidence 结构严重不平衡：138题中 **22题没有 evidence**，105题只有1条，11题有多条。只统计有 evidence 的116题时，单条题占 **90.52%**，多条题占 **9.48%**。
2. “只有1条 evidence”不等于“只需要引用1个条号”。105道单 evidence 题中，有 **29题** 的 `evidence_location` 含多个数字条号，**42题** 的 location 或 text 含多个不同数字条号。evidence 对象数低估了实际应覆盖的条号数。
3. 现有“来源命中但条号未命中”严格口径只有 **19题**，不是20题。本次已将这19题全部列示，相当于全量而非抽样。
4. 这19题中，**3题** 的“来源命中”来自 `_source_match` 的模糊匹配，实际上 Top-5 没有命中期望文档；**16题** 才是期望文档确实进入 Top-5 的条号未命中。
5. 这19题中，系统答案直接引用期望文档的有 **10题**；另外9题虽然 Top-5 可能检索到期望文档，但生成答案没有直接引用它。现有 `source_hit` 评的是检索层，不是答案引用层。
6. 系统答案与 evidence 位于同一文档、同一一级章节的有 **2题**：`FULL-005` 和 `FULL-013`。这两题应计部分命中，而不是完全未命中。
7. 修正后的严格估计：19个名义来源命中条号未命中题中，剔除3个来源伪命中并接受2个同章部分命中后，剩余 **14题** 属于真正的来源正确但条号错位。
8. 建议不要“大范围放宽到同文档即算命中”，而应改为分层评分：文档精确匹配、条号精确匹配、同文档同章部分命中、仅检索来源命中、答案未引用分层记录。

## 2. 分析口径

- 最终评测集138条与系统明细138条按 `source_question_id` 关联，匹配率 **138/138**。
- evidence 条数按 JSON 中 `evidence` 数组元素数统计。
- 数字条号通过 `\d+(?:\\.\d+)+` 从 `evidence_location`、`evidence_text` 和系统引用中提取。
- 系统“直接引用”只统计答案中的 `【依据：...】`，`【同类机理参考：...】` 不用于条号命中判断。
- “同一文档”按文档名称精确归一化判断；“同一章节”按数字条号的第一层编号判断，例如 `49.4` 与 `49.7` 同属第49章，`4.1.6` 与 `4.2.9` 同属第4章。
- 现有明细中的 `source_hit` 使用 `scripts/run_138_evaluation.py` 的 `_source_match`，其规则允许2至4字 n-gram 覆盖率不低于65%，因此可能把文件名相近但实际不同的文档判为命中。

## 3. evidence 结构统计

### 3.1 总分布

- **0条 evidence：22题，15.94%**。
- **1条 evidence：105题，76.09%**。
- **2条 evidence：11题，7.97%**。
- evidence 总条数：127条；平均每题0.92条；在116道有 evidence 的题中平均1.09条。
- 全部127条 evidence 均有非空 `source_file`、`evidence_location`、`evidence_text`；题内没有完全重复的三元组。

按模块：

- 发电机：14题，0条1题，单条11题，多条2题。
- 锅炉：44题，0条21题，单条21题，多条2题。
- 汽轮机：80题，0条0题，单条73题，多条7题。

### 3.2 多条 evidence 的内部结构

- 11道多条 evidence 题中，7题的多条 evidence 来自同一文档，4题来自多个文档。
- 2题的多条 evidence 具有完全相同的 `evidence_location`，其余9题有多个 location；即使 location 相同，`evidence_text` 也不同。
- 因此多条 evidence 既用于“同文档不同条号”，也用于“同条号不同段落”或“跨文档证据补充”。

### 3.3 单条 evidence 内部的隐含多条号

这是本次分析最重要的结构发现：

- 105道单 evidence 题中，**29题** 的 `evidence_location` 含两个及以上不同数字条号。
- 105道单 evidence 题中，**42题** 的 `evidence_location` 或 `evidence_text` 至少含两个不同数字条号。
- 单 evidence 题中有 **25题** 的 location 显式使用条号范围，例如 `32.3.1-32.3.6`。
- 138题按 location 中的数字条号数量分布为：0个65题，1个40题，2个6题，3个27题。
- 换言之，**33题** 的 location 本身就包含2至3个数字条号，但其中多数仍只被存成一个 evidence 对象。

因此，“参考答案只给一条 evidence”不能直接解释为“答案只需要一个条号”。更准确的说法是：**标注对象粒度不一致**。有的单对象只覆盖一条正文，有的单对象覆盖一串条号范围或多个处理条款。

- 系统并非没有给出原因和处理措施，多数答案会引用轴承案例、RCM失效模式、缺陷分析单或另一份规程。

## 5. 评估偏差估计

### 5.1 来源命中口径偏差

- 现有 `source_hit` 使用文件名 n-gram 模糊匹配，19题中有 **3题** 是实际文档不同的伪命中：`FULL-008`、`FULL-034`、`FULL-129`。
- 上述3题把“相似目录、相似年份、相似机组名”的不同文档判为同一来源，会高估来源命中率。
- 建议主指标先做精确文档名匹配；模糊匹配只保留为诊断指标，不能直接进入主命中率。

### 5.2 检索命中与答案引用不一致

- 19题中，期望文档确实进入 Top-5 的为16题。
- 19题中，系统答案直接引用期望文档的只有10题；另外9题没有直接引用期望文档。
- 在16道精确 Top-5 来源命中中，有6题答案完全没有直接引用该期望文档：`FULL-138`、`FULL-045`、`FULL-046`、`FULL-049`、`FULL-041`、`FULL-124`。
- 因此目前报告中的“来源命中”是检索器指标，不是“答案引用了正确来源”的生成指标，两者应拆开。

### 5.3 同文档同章节部分命中的影响

- 19题中，同文档同章节的有2题：`FULL-005`、`FULL-013`，占比 **10.53%**。
- 其中 `FULL-013` 的章节主题一致，部分命中依据较强；`FULL-005` 属于同章不同小节，建议按0.5分部分命中或至少人工复核。
- 同文档但不同一级章节的有8题，包括 `FULL-134`、`FULL-066`、`FULL-048`、`FULL-040`、`FULL-123`、`FULL-125`、`FULL-010`、`FULL-001`。其中部分答案在语义上相关，尤其 `FULL-010` 涉及振动评定限值，可能适合语义等价复核，但不应仅因同文档就自动给条号命中。
- 不同文档且无期望文档直接引用的为9题，主要是缺陷分析单、RCM失效模式、另一台机组的规程或案例替代。

### 5.4 修正后的误差估计

- 名义集合：19题来源命中、条号未命中。
- 剔除3题模糊来源伪命中后：16题期望文档确实进入 Top-5，但条号未命中。
- 接受2题同文档同章节部分命中后：剩余14题属于真正的文档正确但章节或条号错位。
- 全量条号精确命中原为24/73，即32.88%。若把2题同章部分命中单独记为部分命中，则精确命中仍为24/73，部分命中为2/73，即2.74%；若评测规则允许部分命中计入命中，则合并命中为26/73，即35.62%。

## 6. 建议：是否需要放宽评测标准

结论：**需要修订，但不建议大范围放宽。**

建议将单一的二值命中改为分层评分：

1. **精确命中**：文档名精确匹配，且系统引用条号与任一 expected 条号相同。记1.0。
2. **同文档同章部分命中**：文档名精确匹配，且系统引用条号与 expected 条号的一级章节相同。记0.5，并保留人工复核。
3. **同文档同主题部分命中**：文档名精确匹配，条号不同但章节标题或设备主题明确等价，例如同为旋转分离器维护。记0.5或进入人工复核。
4. **同文档弱相关**：只同文档、不同章节且主题不明确等价。记0.25或仅记为来源命中，不计条号命中。
5. **跨文档替代**：文档不同，即使机理相近，也只在“替代证据合理性”指标中加分，不能替代 expected 条号命中。
6. **检索命中但答案未引用**：检索指标可记来源命中，答案引用指标记未引用，避免把召回误当成生成质量。

同时建议修订统计口径：

- 不要把22道无 evidence 题放入来源命中率或条号命中率分母，应单列为“无可评参考答案”。
- 对多 evidence 题计算 expected 条号集合，系统命中任一 expected 条号即算该题命中；同时报告条号覆盖率，避免多答案题只按单点命中。
- 对单 evidence 但 location 或 text 含多条号的题，先展开为条号集合，再计算命中。
- 至少拆分以下指标：检索来源命中率、答案引用来源命中率、精确条号命中率、同章部分命中率、跨文档替代率和人工复核率。
- 当前知识库中相似文件名较多，应优先修复来源归一化和文档别名表，而不是继续放宽条号匹配阈值。

## 7. 最终建议

- 若目标是继续用现有报告做快速回归，可以保留精确条号命中为主指标，同时新增“同文档同章部分命中”作为辅助指标。
- 不建议把“同文档”直接等同于“条号命中”。本次19题中只有2题满足同文档同章节，放宽到同文档会把另外8题不同章节的答案也过度计分。
- 本次证据足以确认：评测集确实存在“单 evidence 对象承载多个条号”的结构性问题，且当前来源命中率有约3/19的模糊匹配假阳性。
- 下一步应优先调整 `scripts/run_138_evaluation.py` 的计分口径和报表字段，而不是修改 `evaluation_dataset_final.json`。
