# CUR-003 回归修复报告

> 日期：2026-10-05
> 修改文件：`scripts/run_regression.py`

## 1. 回归问题

CUR-003 使用问题：

```text
汽轮机振动导致轴承温度高
```

原断言要求最终 Top-5 的 `domain` 集合同时包含：

```text
turbine + auxiliary
```

## 2. 实际行为

路由结果：

```text
intent = multi
intents = ['turbine', 'auxiliary']
route.domains = ['turbine', 'fault_cases', 'auxiliary']
adjacent_domains = ['turbine', 'generator_electrical', 'auxiliary', 'boiler']
```

合并域检索后的实际 Top-5 domain：

```text
['turbine', 'boiler', 'turbine', 'turbine', 'fault_cases']
```

`auxiliary` 记录在本次排序中位于第 9 名，没有进入 Top-5：

```text
rank 9  auxiliary  28.3 负荷高
```

## 3. 诊断结论

这不是路由或域过滤失败：

| 检查项 | 结果 |
|---|---|
| 多意图识别 | 正确，识别为 `turbine + auxiliary` |
| `route.domains` | 正确包含 `turbine`、`fault_cases`、`auxiliary` |
| 是否有 auxiliary 候选 | 有，第 9 名 |
| 是否丢失 auxiliary 数据 | 否 |
| 是否是合并相邻域导致路由缺失 | 否 |
| 原断言是否合理 | 否，断言把“路由覆盖”误写成“Top-5 排名覆盖” |

Top-5 是排序结果，不承诺每个主域或相邻域都保留一个名额。尤其在引入相邻域参与后，Top-5 可能包含 turbine、boiler、fault_cases 等高排序记录，但仍不包含 auxiliary。CUR-003 的正确验证对象应是 `route.domains`，而不是最终 Top-5 domain 集合。

## 4. 修复内容

更新 `scripts/run_regression.py` 中两处 CUR-003 断言：

- 从检查 `result["chunks"]` 的 domain 集合，改为检查 `result["route"]["domains"]`。
- 仍记录 `top5_domains` 作为诊断信息，不隐藏排序结果。
- 用例名称改为“路由包含两个域”，与真实契约一致。

```python
route_domains = set(result.get("route", {}).get("domains") or [])
top5_domains = {chunk.get("domain") for chunk in result["chunks"]}
passed = {"turbine", "auxiliary"}.issubset(route_domains)
```
