# 考题八 · 技术路线调研：大模型知识增强的变压器故障根因分析（现状与优劣）

> 用途：对应技术向「任务1 调研现状、分析不同方案特点」与综述「知识增强技术现状」一节。
> 版本 v0.1｜2026-09-09｜建议与 docs/01_文献调研清单.md 对照引用。

## 0. 一句话现状

主流已从「裸提示/长上下文」演进到「向量 RAG → GraphRAG / Agentic RAG」；而在**工业诊断**这类高严谨场景，业界共识是：**规则/机理知识是不可逾越的约束层，LLM 主要承担"检索→解释→组织报告"的角色**，而不是让它自由发挥。下面从三个正交视角拆解路线，避免把不同层面的东西混为一谈。

---

## 1. 视角一：知识注入路线（怎么让 LLM "学会"领域知识）——4 条

### 路线 A1｜提示工程 / 长上下文（不建知识库）
做法：把相关文档直接塞进 prompt（或用超长上下文窗口）。
- 优点：零工程、见效快、适合少量短文档。
- 缺点：塞不进大量规程；长上下文"中间丢失"、贵、慢；仍会幻觉；**无法规模化、无法溯源到具体库**。
- 定位：只作基线/兜底，不作为主线。

### 路线 A2｜向量 RAG（检索增强生成）★当前主流基线
做法：文档切块→Embedding→向量库(Chroma)→检索 Top-k→LLM 带引用生成。
- 优点：①免训练、文档可随时换（规程改版直接替换）②输出可溯源到原文块 ③成本低、门槛低，2 周可跑通 ④有效缓解幻觉（只答检索到的内容）。
- 缺点：①检索质量决定上限——切分不当/问题表述偏差会漏检 ②只做"语义相似"匹配，**不懂"设备-部件-故障"之间的拓扑关系**，跨文档推理弱 ③检索错了照样可能生成错结论。
- 细分（进阶 RAG 技巧，报告里可列）：Naive → Advanced（混合检索/rerank/HyDE）→ Modular/Self-RAG/CRAG（自判断何时检索、检索纠错）。
- 权威分类：Gao et al., Retrieval-Augmented Generation for Large Language Models: A Survey, arXiv:2312.10997。

### 路线 A3｜知识图谱 / GraphRAG 增强
做法：先建"设备-部件-故障现象-特征气体-处置"知识图谱（KG），检索时沿图结构取子图/社区，或走 GraphRAG 全局摘要。
- 优点：①显式表达**拓扑/因果/规则关系**（正好对应题面"拓扑关系难组织"）②多跳推理、跨文档关联强 ③比纯向量更"机理可解释"。
- 缺点：①建图成本高——从非结构化规程里抽实体/关系又难又易错（需要 LLM 辅助抽取+人工校对）②图谱维护负担 ③工程量大，1 个月 MVP 有风险。
- 定位：**加分项/第二阶段**；若做，先用小规模"现象→故障→处置"关系图，别贪全。
- 权威分类：Pan et al., Unifying Large Language Models and Knowledge Graphs: A Roadmap, arXiv:2306.08302（KG-enhanced LLMs / LLM-augmented KGs / Synergized）；Edge et al., GraphRAG, arXiv:2404.16130；变压器 KG-RCA 案例：Martinez-Gil et al. 2022（docs/01 C1）。

### 路线 A4｜领域微调（SFT / LoRA）
做法：用领域语料对 LLM 做有监督微调（LoRA/QLoRA 低成本版）。
- 优点：①模型"内化"领域表达与输出格式，单次推理更省 token ②风格/术语更稳。
- 缺点：①要 GPU 与高质量标注数据（实验室只给 API 额度，**无 GPU 现实**）②知识"学进参数里"后**不可溯源、更新要重训** ③小规模微调仍会幻觉、机理严谨性提升有限。
- 定位：**明确不选**——在报告里写清"为什么不用微调"（可溯源性、算力、更新成本），这本身是加分论述。

> 总结视角一：A2 是"性价比最优且可溯源"的主线；A3 补关系推理；A4 因约束不可行；A1 仅兜底。

## 2. 视角二：诊断逻辑路线（结论怎么产生、靠不靠得住）——3~4 条

### 路线 B1｜规则/机理法（确定性基线）
做法：DL/T 722-2014 / IEC 60599 的三比值、注意值、Duval 三角等，把气体数据映射到故障类型。
- 优点：①完全可解释、可复核、**天然合规**（依据就是规程条文）②无需训练、稳定。
- 缺点：①覆盖面有限：只覆盖油色谱判据覆盖的故障 ②边界/组合情况判不准（单一判据有盲区，如 Duval 对某些放电不敏感）。
- 定位：**知识库的"规则底座"+ 评测时的"标准答案生成器"**，不是被淘汰的旧东西。

### 路线 B2｜数据驱动（ML/DL 分类）
做法：用 IEC TC10 等 DGA 数据训 SVM/神经网络/树模型做故障分类。
- 优点：能拟合复杂非线性、样本充足时精度高。
- 缺点：①工业故障样本稀缺（严重故障少、标注贵）②黑箱难解释、难合规 ③与"机理约束/可溯源"赛题目标相悖。
- 定位：**只做对比基线**（证明"数据驱动精度≠可合规交付"），不建议作为交付主线。

### 路线 B3｜LLM 直接推理（纯生成）
做法：只靠 LLM 常识/提示回答诊断问题。
- 优点：零成本起步、语言自然。
- 缺点：变压器领域知识不在其训练里或已过时；**幻觉高风险、给出危险处置建议**——正是题面警告的"缺乏工业认知的大模型极易产生幻觉与危险建议"。
- 定位：只用作"对照组"（有知识库 vs 无知识库的消融），证明你们系统的价值。

### 路线 B4｜混合（规则约束 + RAG + LLM 生成）★推荐
做法：规则/机理判据先给出**确定性诊断骨架**（故障类型、依据条文），RAG 检索补充"案例/处置/条文细节"，LLM 只负责组织成规范报告并**强制引用**；最后用规则校验器+人工复核把关。
- 优点：①机理严谨性由规则兜底、语言灵活性由 LLM 提供（各取所长）②可溯源、可复核、可合规 ③符合题面"依托领域知识进行机理约束"的核心诉求。
- 缺点：需要做一层"规则→文本"的映射工程（把规程判据结构化），前期略费工。

## 3. 视角三：系统形态（怎么编排多步排障）——3 级

- **C1｜单轮问答**：一问一答。简单但不会"先查规则→再假设→再验证→出报告"，排障深度不够。
- **C2｜Agent 多步工作流（Agentic RAG）**：LLM + 工具/检索循环（ReAct：想→查→看结果→再想），可自选检索时机、自我修正（Reflexion）、边查边记录证据链。**考题点名要设计 Agent Workflow，主线应落在 C2。**
  参考：RCAgent（arXiv:2310.16340）、Exploring LLM-based Agents for RCA（arXiv:2403.04123）、DiagAgent（电力设备，RAG+MCP）。
- **C3｜人机协同/人工复核**：关键处置建议必须人工确认（对应"处置建议保留人工复核关口"）。不是技术路线，但是**合规底线**，报告里要作为系统设计的一部分写明。

## 5. 我们的选型建议（MVP 组合拳）

> **规则机理判据（B1）做"知识底座与标准答案" → 向量 RAG（A2）做"规程条文/案例检索" → Agent 多步工作流（C2）编排"现象解析→检索→假设→验证→报告" → LLM 仅做带强制引用的组织与解释（B4）→ 规则校验器 + 人工复核（C3）兜合规。**

- **必须做**：A2 + B1 + C2 + C3 的思想（人工复核关口写进方案）。
- **加分项（有时间再做）**：A3 轻量图谱——把"特征气体→故障类型→处置"做成小 KG，先向量后图谱做一次消融对比，报告会非常加分。
- **明确不做**：A4 微调（无 GPU、不可溯源）；B2 只作基线对比、不作为交付。
- **对照组（写评测用）**：纯 LLM（B3）vs 你们系统（B4）→ 证明 RAG/规则约束有效。

## 6. 综述写作时的论述骨架（对应"任务1"）
1. 按视角一给 4 条知识注入路线 + 各自优劣（引 A2/A3/A4 文献）；
2. 指出纯 LLM 在工业诊断的幻觉与危险建议风险（引题面背景 + B3 对照组）→ 引出"机理约束"必要性；
3. 按视角二说明规则/数据驱动/LLM 三类诊断逻辑的互补关系；
4. 按视角三说明为何用 Agent 多步而非单轮（引 RCAgent / E4）；
5. 落到本方案 = B4 混合 + C2 Agent 编排，并给出与每条路线的对比理由。
