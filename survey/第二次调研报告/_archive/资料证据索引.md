## 2. 附件内容与项目动作

| 资料观点 | 项目动作 | 优先级 |
|---|---|---|
| RAG 需要外部非参数记忆 | 保留 BM25 + 向量混合检索与条号证据 | 已实现 |
| 现代 RAG 架构族应按任务选择 | RAG 为 MVP，GraphRAG/多模态后置 | 已决策 |
| 动态图路由适合不同复杂度查询 | 先做意图路由，图谱动态路由后置 | P2 |
| GraphRAG 多跳可连接实时告警与非实时记录 | 先建轻量证据图谱，不建完整图谱 | P2 |
| EvLink 强调来源可追溯 | 引入 evidence_id、原文匹配和证据边 | P0/P1 |
| ReAct 用 Thought→Action→Observation 协同推理和行动 | 受控 Agent 增加步数上限、工具白名单和证据终止锚点 | P1 |
| Self-RAG 按需检索并判断相关性、支持度和有用性 | 增加检索质量标签和证据支持判断 | P1 |
| CRAG 评估检索质量并执行精炼、丢弃或回退 | 仅在本地规程库、规则引擎和补数流程内回退，不使用公开 Web | P1 |
| RCAgent 使用 Controller/Expert 分层 | Agent 使用白名单专家工具，不允许自由访问数据库 | P1/P2 |
| OBSK 用外部存储控制长观察 | 规程、案例和巡检记录存证据库，prompt 只放摘要头与 ID | P1 |
| JsonRegen 与错误反馈提高动作有效性 | 结构化输出 schema、有限重试和非法动作拦截 | P1 |
| TSC 可聚合候选根因 | 只用于候选排序，规则拥有最终否决权 | P2 |
| 多模态晚期融合适合弱相关模态 | 先用规则+文本证据晚期融合，多模态后置 | P2 |
| LoRA 适合固定任务适配 | 不作为规程知识更新的主路线 | P2 |
